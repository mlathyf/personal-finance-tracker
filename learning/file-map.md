Task 6.5: the `amount` input briefly changed to `type="text"` after decimals (e.g. `13.99`) were rejected by `type="number"`'s default `step="1"`; corrected back to `type="number" step="0.01"` after discussing the tradeoff (native numeric keyboard/validation vs. accepting anything) — confirmed a decimal amount now submits and stores correctly as cents. |
| `public/style.css` | known | Basic layout/spacing for the page — box-sizing reset, centered body, flexbox form layout, styled inputs/select/button — written by you in Section 3. |
| `public/script.js` | known | Frontend JS, loaded via `<script defer>` at the bottom of `index.html`. Grabs the form, container, and each field. `renderExpense(expense)` (extracted in 5.6 to remove duplication) builds a `<div>` row from an expense object and `prepend()`s it into `#container`. `fetchExpenses()` (5.5) runs on page load, fetches `GET /api/expenses`, and calls `renderExpense` per item. The `submit` handler (5.6) now builds an object from the form's live values, `POST`s it (with `JSON.stringify`) to `/api/expenses`, awaits the server's response (the created object, real `id` included), renders it via `renderExpense`, and resets the form. Confirmed end-to-end: submitted expenses persist across a page refresh. |
| `server.js` | known | The backend entry point. Imports Express and `better-sqlite3` (`const Database = require("better-sqlite3")`), opens/creates `expenses.db` via `const db = new Database("expenses.db")`, creates the app. Task 6.2: runs `db.exec(\`CREATE TABLE IF NOT EXISTS expenses (id INTEGER PRIMARY KEY, amount INTEGER, date TEXT, category TEXT, note TEXT)\`)` on every startup — `amount` deliberately stored as integer cents (not `REAL`) to avoid floating-point rounding error on money; `date` as `TEXT` in ISO-8601 since SQLite has no native date type and that format sorts correctly as plain text; confirmed idempotent (safe across restarts) via `.schema`. Registers `express.static("public")` and `express.json()` as middleware. `GET /api/expenses` (task 6.3) runs a fresh query on every request: `res.json(db.prepare("SELECT * FROM expenses").all())`. `POST /api/expenses` (task 6.4) now writes to the real database instead of memory: destructures `req.body`, converts the incoming dollar string to integer cents (`const amountCents = Math.round(parseFloat(amount) * 100)`), runs a parameterized `INSERT` (`db.prepare("INSERT INTO expenses (amount, date, category, note) VALUES (?, ?, ?, ?)").run(amountCents, date, category, note)` — placeholders keep user input as data, never as SQL syntax, avoiding SQL injection), then builds the response object using `result.lastInsertRowid` as the real database-assigned `id`. The old in-memory `expenses` array and `nextId` counter (task 5.2) are gone — deleted once nothing read from them anymore. Known open gap (not yet fixed, tracked as plan task 7.5): the frontend still renders `amount` as a raw integer (e.g. `1999`) with no cents-to-dollars formatting. Then `app.listen(3000, ...)` with a confirmation log. |
