## Project root

| Path | Status | What it is / why it exists |
|---|---|---|

| `package.json` | parked | npm's manifest: project name, dependencies (Express), and what `main` file to run. Content generated by `npm init`; you added the `scripts.start` entry yourself in Section 4 so `npm start` runs `node server.js`. Other fields (`dependencies`, `main`, `version`) still not walked through concept-by-concept. |
| `package-lock.json` | generated | Exact versions of every installed dependency, written automatically by npm so installs are reproducible. Never hand-edit. |

| `public/` | known | Holds the frontend (HTML/CSS/JS). |
| `public/index.html` | known | The app's skeleton: heading, empty `#container` for the expense list, and the add-expense form (amount/date/category/note) with labels — written by you in Section 2; now links `style.css`, no JS behavior yet. |
| `public/style.css` | known | Basic layout/spacing for the page — box-sizing reset, centered body, flexbox form layout, styled inputs/select/button — written by you in Section 3. |
| `public/script.js` | known | Frontend JS, loaded via `<script defer>` at the bottom of `index.html`. Grabs the form, container, and each field. `renderExpense(expense)` (extracted in 5.6 to remove duplication) builds a `<div>` row from an expense object and `prepend()`s it into `#container`. `fetchExpenses()` (5.5) runs on page load, fetches `GET /api/expenses`, and calls `renderExpense` per item. The `submit` handler (5.6) now builds an object from the form's live values, `POST`s it (with `JSON.stringify`) to `/api/expenses`, awaits the server's response (the created object, real `id` included), renders it via `renderExpense`, and resets the form. Confirmed end-to-end: submitted expenses persist across a page refresh. |
| `server.js` | known | The backend entry point. Imports Express, creates the app, declares module-scope `const expenses = []` and `let nextId = 1` (task 5.2), registers `express.static("public")` and `express.json()` as middleware, defines `GET /api/expenses` (task 5.3, confirmed live), and `POST /api/expenses` (task 5.4) which object-destructures `req.body`, builds an `expense` object with an auto-incrementing `id`, pushes it onto `expenses`, and responds `201` with the created object — confirmed live via `curl`. Then `app.listen(3000, ...)` with a confirmation log. |
| `.gitignore` | known | Lists what Git should never track. Written by hand: `node_modules/` (huge, reproducible via `npm install`) and `.DS_Store` (macOS Finder junk file). |
| `.git/` | generated | Git's internal database for this repository (branch pointer, settings, and — once commits exist — every stored version of every file). Never hand-edit; standard contents are `HEAD`, `config`, `objects/`, `refs/` (the ones that matter) plus `hooks/`, `description`, `info/` (legacy/unused for this project). |
